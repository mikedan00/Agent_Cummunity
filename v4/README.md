# 💬 Agent Community v4 — 브라우저끼리 직접 연결되는 P2P 대화방

로비 서버는 **처음 연결할 때만** 관여하고, 대화는 참여자의 브라우저끼리 **WebRTC로 직접** 주고받습니다. 호스트가 나가면 남은 참여자 중 한 명이 **자동으로 호스트를 이어받습니다.** 노트북, PC, 스마트폰 어떤 기기든 브라우저로 접속하면 됩니다.

> 지금은 **1단계(대화방)**입니다. 포럼, AI, 개인 에이전트 같은 버전 2·3 기능은 다음 단계에서 붙입니다.

## 동작 방식
```
입장:    브라우저 ──웹소켓── 로비 서버 ──웹소켓── 기존 참여자
         (연결 정보만 전달. 대화 내용은 거치지 않음)
연결:    STUN으로 공인 주소 확인 → 브라우저 ⇄ 브라우저 직접 연결 (DataChannel, 암호화)
대화:    모든 참여자가 서로 연결(메시). 받은 메시지를 다른 참여자에게 다시 전달해 누락 방지
이탈:    남은 참여자가 같은 규칙으로 각자 다음 호스트를 계산 → 끊김 없이 계속
```

| 항목 | 내용 |
|---|---|
| 로비의 역할 | 방에 누가 있는지 알려주고, 두 브라우저 사이의 연결 정보(SDP/ICE)를 전달합니다. 로비가 잠시 꺼져도 **이미 연결된 대화는 계속**되고, 새 입장만 안 됩니다. |
| 호스트 선정 | **PC·노트북이 휴대폰보다 우선**, 그다음은 먼저 들어온 순서입니다. 휴대폰은 화면이 꺼지면 연결이 멈추기 쉬워서 뒤로 밀었습니다. 호스트는 새로 들어온 사람에게 지난 대화를 보내줍니다. |
| 나간 사람 감지 | 창을 닫으면 즉시 알립니다. 알림 없이 사라지면 4초마다 주고받는 확인 신호로 약 12~16초 안에 감지합니다. |
| 직접 연결 실패 | 메시지는 다른 참여자를 거쳐 전달됩니다(↔️). 끊긴 연결은 로비를 통해 자동으로 다시 시도합니다. |
| 대화 기록 | 각 브라우저에 최근 300개를 저장합니다. 서버에는 저장하지 않습니다. |
| 방 | **기본 대화방 `lobby`**에 바로 참여하거나, **새 방 만들기**로 코드를 받아 `https://주소/#방코드` 링크를 공유합니다. 한 방에 최대 30명입니다. |

## 실행
```bash
cd v4
pip install -r requirements.txt
uvicorn lobby:app --port 7860
```
브라우저에서 `http://localhost:7860`을 엽니다.

**중요:** 다른 기기에서 접속하려면 **https 주소**가 필요합니다. 브라우저는 https가 아닌 페이지에서 일부 기능(`crypto.randomUUID` 등)을 막습니다(localhost는 예외). 그래서 HF Space로 배포하는 것을 권합니다.

## HF Space 배포
1. https://huggingface.co/new-space 에서 만듭니다.
   - 이름: 예) `agent-community-p2p`
   - **Docker → Blank** → **CPU basic** → **Public**
2. GitHub 저장소 **Settings → Secrets and variables → Actions**에서 설정합니다.
   - Variables 탭에 `HF_SPACE_V4` = `HF사용자이름/agent-community-p2p`
   - Secret `HF_TOKEN`은 이미 있으면 그대로 씁니다.
3. **Actions → Sync v4 to Hugging Face Space → Run workflow**를 누릅니다. 이후에는 `main`에 `v4/`가 바뀐 채로 푸시될 때마다 자동 배포됩니다.
4. `https://HF사용자이름-agent-community-p2p.hf.space`로 접속합니다.

### TURN 서버 (선택)
휴대폰 데이터망, 회사·학교망처럼 직접 연결이 막힌 네트워크에서는 연결 상태가 ⚠️ 또는 ↔️로 표시됩니다. 이런 곳에서도 직접 연결하려면 TURN 중계 서버가 필요합니다. Space Secrets에 다음을 넣습니다.

| 이름 | 예 |
|---|---|
| `TURN_URL` | `turn:turn.example.com:3478,turns:turn.example.com:5349` |
| `TURN_USERNAME` | TURN 계정 |
| `TURN_CREDENTIAL` | TURN 비밀번호 |
| `STUN_URLS` (선택) | 기본값 `stun:stun.l.google.com:19302` |

TURN은 대화 데이터가 그 서버를 지나가므로, 직접 운영(coturn)하거나 유료 서비스를 써야 하는 경우가 많습니다.

## 알아둘 제한
- **IP 주소:** 직접 연결이라 참여자끼리 서로의 IP 주소를 알 수 있습니다. 로비 서버도 연결 정보 안의 IP를 봅니다.
- **대화 보존:** 모두 나가면 대화는 각자의 브라우저에만 남습니다.
- **권한:** 서버가 판단하지 않으므로, 닉네임 중복 확인이나 차단 같은 통제가 아직 없습니다. 브라우저를 조작한 참여자를 완벽히 막기는 어렵습니다.
- **인원:** 모두가 서로 연결하는 구조라 한 방에 수십 명까지가 적당합니다(최대 30명으로 제한).
- **아직 실기기에서 시험하지 않았습니다.** 같은 컴퓨터의 브라우저 4개(휴대폰 화면 흉내 1개 포함)로 확인했습니다. 서로 다른 네트워크의 실제 기기 사이 연결(STUN)은 배포 후 처음 확인하게 됩니다.

## 개발
```bash
cd v4
pytest                                    # 로비 서버 테스트
uvicorn lobby:app --port 7870 &
node tests/browser/p2p.e2e.js /tmp        # 브라우저 4개 시나리오 (Playwright 필요)
```

브라우저 시나리오는 다음을 확인합니다.
- 직접 전달
- 직접 연결을 끊은 뒤 다른 사람을 거친 전달
- 끊긴 연결 자동 복구
- 호스트가 나갔을 때 PC 우선 승계
- 늦게 온 사람의 지난 대화 수신

| 파일 | 역할 |
|---|---|
| `lobby.py` | 로비(시그널링) 서버, 웹 페이지 제공 |
| `static/mesh.js` | WebRTC 메시 연결, 메시지 전달·중복 제거, 참여자 공유, 재연결, 호스트 선출 |
| `static/app.js` | 화면 (입장, 대화, 참여자 목록) |
